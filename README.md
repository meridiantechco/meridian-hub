# Prospector Hub

Quero construir um sistema web (SaaS interno) chamado "Prospecta" para localizar e gerenciar leads de empresas locais que não possuem site próprio (lojas, restaurantes, salões, oficinas, corretores de imóveis, petshops, etc). O sistema serve para minha equipe comercial priorizar e abordar esses estabelecimentos oferecendo criação de site/landing page. ### Stack e integrações - Frontend: React + Tailwind, usando Supabase como backend (auth, banco de dados e edge functions). - Autenticação: login por e-mail/senha, com papéis de usuário (admin e vendedor). - Integração externa: API do Google Places (New) para buscar estabelecimentos por categoria + região e detectar se possuem site cadastrado. - Não incluir, por enquanto, nenhuma integração com WhatsApp Business API. Contato via WhatsApp deve ser apenas um link "wa.me" manual gerado a partir do telefone. ### Modelo de dados (tabelas principais) 1. leads - id, nome, categoria, endereço completo, bairro, cidade, estado, latitude, longitude, telefone, whatsapp_link (gerado), instagram, facebook, site_url (nullable), tem_site (boolean calculado), avaliacao_google (decimal), total_avaliacoes (int), place_id (do Google Places, único), status (enum: novo, contatado, proposta, fechado, recusado), score (int calculado), origem (enum: google_places, manual, importacao), responsavel_id (fk users), observacoes (texto), criado_em, atualizado_em. 2. buscas - histórico de buscas feitas na API do Google Places: id, termo_busca, categoria, cidade/região, raio_km, total_resultados, total_sem_site, executada_por (fk users), criada_em. Serve para não repetir buscas e permitir re-execução. 3. interacoes - histórico de contatos com cada lead: id, lead_id (fk), tipo (enum: ligacao, whatsapp, email, visita, outro), descricao, resultado, usuario_id, criado_em. 4. users - id, nome, e-mail, papel (admin, vendedor), criado_em. ### Regra de negócio: cálculo de "score de prioridade" Calcular um score de 0 a 100 por lead, combinando: - Não ter site próprio (peso alto) - Ter Instagram/Facebook mas sem site (site "fraco" — ainda soma pontos, peso médio) - Número de avaliações no Google (mais avaliações = mais pontos, com teto) - Nota média no Google (quanto maior, mais pontos) - Recência da captura do lead (leads mais recentes pontuam um pouco mais, para priorizar contato rápido) Exiba o score como um número inteiro com uma barra/indicador visual de prioridade (alta, média, baixa). ### Funcionalidades principais 1. **Busca de novos leads (tela "Nova busca")** - Formulário com: categoria/segmento de negócio (texto livre + sugestões comuns: restaurante, salão de beleza, oficina mecânica, corretor de imóveis, loja de roupas, petshop, etc), cidade/bairro, raio de busca em km. - Ao submeter, chamar a API do Google Places (Text Search / Nearby Search) via edge function do Supabase (a chave da API deve ficar apenas no backend, nunca exposta no frontend). - Para cada resultado, verificar o campo de site: se estiver vazio, marcar tem_site = false; se o link for de instagram.com, facebook.com ou linktr.ee, marcar tem_site = false mas guardar esse link como rede social, não como site. - Salvar os resultados na tabela leads, evitando duplicados por place_id. - Mostrar uma tela de revisão antes de salvar, com checkbox para selecionar quais resultados importar. 2. **Painel principal (dashboard)** - Cards de indicadores no topo: total de leads, leads sem site (com percentual), score médio, taxa de conversão (fechados / total). - Mapa mostrando a localização de todos os leads, com cor diferente para "sem site" e "com site" (usar Google Maps JavaScript API ou Leaflet com marcadores; ao clicar no marcador, abrir um card resumido do lead). - Gráfico de barras: quantidade de leads por categoria/segmento. - Gráfico de funil: novo → contatado → proposta → fechado. - Lista/carrossel dos "leads mais quentes" (maior score) ainda não contatados. 3. **Lista de leads (tabela)** - Colunas: nome, categoria, bairro, telefone, Instagram, avaliação Google (nota + qtd), score, status, responsável. - Filtros: por categoria, por bairro/cidade, por status, por "somente sem site", por faixa de score, por responsável. - Busca por nome. - Ordenação por score, avaliação, data de captura. - Ação rápida: link direto para abrir WhatsApp Web (wa.me/[telefone]) com uma mensagem padrão pré-preenchida e editável antes de enviar. - Ação para mudar o status do lead diretamente na tabela (dropdown). 4. **Detalhe do lead** - Todas as informações do estabelecimento (endereço completo, coordenadas em mini-mapa, contatos, redes sociais, avaliação). - Linha do tempo de interações (histórico de contatos), com formulário para registrar nova interação (tipo, descrição, resultado). - Campo de observações livres. - Botão para atribuir/reatribuir o lead a um vendedor (somente admin). 5. **Funil de vendas (kanban)** - Visualização em colunas (novo, contatado, proposta, fechado, recusado) com cards arrastáveis (drag and drop) para mudar o status do lead. 6. **Painel de buscas realizadas** - Histórico de buscas feitas na API do Google Places, com opção de "re-executar" a busca para capturar leads novos que possam ter surgido. 7. **Gestão de usuários (somente admin)** - Listar, convidar e definir papel de vendedores. Cada vendedor só enxerga os leads atribuídos a ele; admin enxerga todos. ### Diretrizes de design - Interface em modo escuro como padrão, com identidade visual inspirada em cartografia/prospecção de campo (mapas, pins, coordenadas), não usar o clichê de fundo bege com sotaque terracota. Paleta sugerida: fundo #11171A, superfícies #1A2226 e #212B30, bordas #2B363B, texto #EDF1F2, cor de alerta/"sem site" em laranja #FF6B35, cor de sucesso/ "fechado" em verde-água #3ECF8E, cor neutra de "novo" em azul #5B8CFF. Tipografia: uma fonte de display geométrica para títulos (ex: Space Grotesk), uma fonte utilitária monoespaçada para dados/telefones/scores (ex: IBM Plex Mono), e uma fonte de texto neutra para o corpo (ex: Inter). - Layout responsivo, com sidebar de navegação fixa em telas maiores e menu colapsável em mobile. - Todos os textos da interface em português do Brasil. ### Segurança - Chave da API do Google Places deve ser armazenada como variável de ambiente/ secret no Supabase, usada apenas dentro das edge functions — nunca exposta no código do frontend. - Regras de RLS (Row Level Security) no Supabase: vendedores só leem/editam leads onde responsavel_id = seu próprio id (a menos que não tenham responsável definido, aí qualquer vendedor pode assumir); admins têm acesso total. Comece criando a estrutura do banco de dados (tabelas acima), a tela de login, o layout base (sidebar + topbar) e o painel principal com dados fictícios (mock), antes de conectar a integração real com a API do Google Places.
